## Short Profile Summary

Scarab Systems investigates public open-source issues, develops scoped patches,
runs repository-native validation, and records merged outcomes in the public
Scarab Field Lab. Sponsorship supports dedicated time for diagnostics, patch
development, regression testing, documentation, and maintainer follow-through.

## Full Introduction

Scarab Systems works on difficult public open-source issues where a useful patch
requires careful diagnosis before code changes. The current public record
includes 16 merged contributions across 11 repositories, including Docker
Compose, Electron, Microsoft Agent Framework, NVIDIA/NemoClaw, pnpm, SvelteKit,
Directus, OpenAPI Generator, Open Multi Agent, Twenty, and
xdg-desktop-portal-wlr.

The public proof record lives in the Scarab Field Lab:
https://github.com/scarab-systems/scarab-field-lab

Field Lab records document public issue links, merged pull requests, diagnostic
findings, validation summaries, review outcomes, changed public files, and clear
non-claims. The work spans developer tooling, container tooling, Linux desktop
infrastructure, web frameworks, package management, application platforms, AI
infrastructure, and agent systems.

Sponsorship creates dedicated time for public open-source diagnostics and patch
delivery: selecting real issues, confirming behavior, tracing code paths,
developing scoped fixes, adding or updating tests, running repository-native
checks, responding to maintainer feedback, and recording the public result.

Proprietary diagnostic tooling may support repository analysis, evidence
gathering, patch validation, and scope control. That tooling is not open source
and is not distributed through the Field Lab. Public submissions remain grounded
in the target repository's own code, conventions, tests, maintainer
requirements, and final review.

Sponsorship does not guarantee maintainer review, acceptance, merge, release
inclusion, downstream adoption, or any outcome controlled by third-party
maintainers.

## Existing-Tier Review Notes

The current public tier wording was not accessible from the unauthenticated
GitHub Sponsors page during this edit. Keep the existing four tiers unless the
live tier editor shows minor wording that needs clarification.

Suggested distinction to preserve across the existing tiers:

- Diagnostic report: focused review of a selected public issue, including a
  concise finding, likely failure boundary, reproduction or verification notes
  where available, and implementation guidance.
- Diagnostic report plus patch delivery: diagnostics plus a scoped public patch
  branch or upstream-ready pull request where appropriate.
- Monthly support: recurring support for public open-source diagnostics, patch
  development, regression testing, documentation, and contribution
  follow-through.
- One-time engagement: a bounded one-time public issue review or diagnostic
  plus patch engagement, depending on the selected tier.

Avoid wording that promises guaranteed merges, unlimited support, fixed
resolution times, maintainer acceptance, release inclusion, or downstream
adoption.
